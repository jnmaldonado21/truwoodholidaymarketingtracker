# TruWood Q4 2026

Everything that has to happen between 27 October and 5 January, in one place.
95 tasks, pulled from the Master Q4 / BFCM Operational Checklist and the
Pre-BFCM Strategy deck. Most of them carry step-by-step instructions: click a
task and read "How to do it".

If you have never used GitHub before, you only need the three things in
"How to use this" below. Nothing here involves code.

---

## The two views

Open the **TruWood Q4** project (the Projects tab at the top of this repo).

**Roadmap** is the calendar view. Every task sits on the day it is due, and the
rows are grouped by campaign phase. Use it to see what is coming and how much
is landing in the same week.

**Board** is the to-do view: Todo, In Progress, Done. Drag a card across as the
work moves. This is the one to live in day to day.

Both views show the same tasks. Changing something in one changes it in the other.

---

## How to use this

**1. Find your work.** In the Board or Roadmap view, use the filter box at the
top and type `label:owner:taylor` (or `owner:nolan`, `owner:gbe`,
`owner:charlie`, `owner:j`). That hides everyone else's tasks.

**2. Say what is happening.** Click a task to open it, then type in the comment
box at the bottom. This is where questions, blockers and decisions should go,
rather than in a thread somewhere else — the point is that the next person to
look at the task can see what happened without asking.

**3. Read the steps.** Most tasks have a numbered "How to do it" on them. If a
task has none and you are unsure what it means, say so in a comment rather than
guessing — that is a gap worth filling.

**4. Attach files.** Drag an image, a PDF, a spreadsheet, anything, straight
into that comment box. It uploads and attaches to the task. Design proofs,
screenshots of a broken page, an export from Klaviyo — put them on the task
they belong to.

**Moving a task:** drag its card between columns on the Board, or open it and
change Status on the right-hand side.

**Blocked on someone?** Add the `blocked` label and say why in a comment. Blocked
tasks with no comment explaining the block are the main way a plan quietly
falls apart.

## What the labels mean

| Label | Meaning |
| --- | --- |
| `owner:*` | Who is doing it. Tasks shared between two people carry both labels. |
| `type:decision` | **Nothing downstream can start until this is decided.** Four of these, all in the first two weeks. |
| `type:site-change` | A live change to mytruwood.com on that day. Eleven of these. |
| `type:website` | Storefront build work, all Nolan. |
| `type:content` | Writing and adding page content, all J. |
| `type:build` | Campaign production — email, SMS, social, ads, creative. |
| `type:qa` / `type:support` | Testing, and customer-support prep. |
| `blocked` | Cannot proceed. Say why in a comment. |
| `risk` | Flagged in the risk register in the plan document. |

Milestones are the ten campaign phases, each with the date that phase ends.

## The dates

Each task shows **Work on it by** at the top of its description. Where that
differs from the original checklist deadline, the original is listed further
down with a note. Those were changed in one direction only: several multi-day
jobs had been stacked onto a single date, so each was given a realistic date
tied to the first send that depends on it. No work was removed.

Three dates worth knowing without looking them up:

- **Fri 27 Nov** — Black Friday. The only change that day is switching the
  discount from a VIP code to automatic. Nothing else should be scheduled near it.
- **Sun 15 Nov** — the Christmas creative deadline falls on a weekend.
- **Sat 26 Dec** — the Gift Yourself storefront change is the day after
  Christmas, and someone has to physically do it.
